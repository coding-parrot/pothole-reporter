Provenance is not proof

The app combines a user's camera and phone location with public reference data, local rules, and AI judgments. A cited record does not prove that a photographed defect is reportable, that a particular authority owns the road, or that a contractor or warranty applies.

Review the photo, recipient, wording, and any probable contract match before sending a complaint.

What comes from where

OutputSource or methodImportant limit
Road image and coordinates The user's camera and the phone's Android location service. Camera angle, motion, lighting, GPS accuracy, and stale fixes can all be wrong or incomplete.
Damage type, assessment, size, and description An OpenAI vision model evaluates selected image views under the app's prompt and schema. This is generated judgment, not ground truth. The current detector does not have a complete held-out, human-labelled field benchmark.
Street address OpenStreetMap Nominatim reverse-geocodes phone coordinates. Map data can be missing, stale, or imprecise. The complaint also includes coordinates so the result can be checked.
Town boundary, gram-panchayat boundary, and national-highway check Karnataka GIS, operated by KSRSAC, is queried at the reported point. A boundary lookup does not by itself establish maintenance responsibility. If the required road-class or jurisdiction lookup fails, the app is designed to refuse municipal routing.
Municipal recipient The bundled directory contains 182 supported local bodies. Addresses were compiled from Karnataka district NIC pages and local-body pages; entries are keyed by Local Government Directory town code. Contact details are a dated snapshot and may change. Bodies without a published address are deliberately unroutable.
Tender number, work title, publication date, and location The current bundle contains 42,283 road-related rows filtered from awarded works on the Karnataka Public Procurement Portal (KPPP). The title-keyword filter is intentionally broad. A tender row is not proof that its work covers the photographed point.
Winning bidder on some Bengaluru records 1,124 bundled rows contain contractor names derived from the public snapshot at bengaluru-road-contracts.pages.dev, whose stated source is KPPP. This is an intermediary snapshot rather than a fresh per-tender lookup. Most bundled rows have no bidder name, and the app must not invent one.
Probable contract match A deterministic local ranking selects up to 25 contracts indexed to the same supported body; an OpenAI model may then select one above the app's confidence threshold. The match is generated and probabilistic. The complaint labels it probable and asks the officer to verify it against tender documents.
Possible defect-liability or maintenance wording A local rule uses the tender's publication date: up to one year is described as possibly within a defect-liability period and up to three years as possibly within maintenance. The award-search row contains no actual warranty term. This is an inference and must never be presented as a contractual fact.
Complaint text and signature A local template combines the reviewed result, coordinates, supported recipient, optional probable contract reference, and the sender name entered in Settings. The user is responsible for checking and editing the draft. The app opens an email composer but does not send the message.

Current bundle boundaries

  • The app covers supported Karnataka urban local bodies with a published recipient address; it does not claim statewide routing for every road.
  • Of 319 urban local bodies in the roster used to build the bundle, 182 have a supported directory entry and 137 do not.
  • Of 42,283 road-related procurement rows, 18,972 are DMA or legacy BBMP records. Only 13,577 are currently indexed to a supported body and can enter a contract shortlist.
  • 41,159 procurement rows have no winning bidder recorded in the bundle.
  • National highways, rural roads, unknown road classes, locations outside Karnataka, and unsupported bodies are not routed to a municipal recipient.
  • All counts describe the repository snapshot above, not the current contents of an external portal.

How to audit it

  1. Use the photo and printed coordinates to check the event itself.
  2. Follow the address and GIS sources above to check location and routing.
  3. Search KPPP by tender number and read the tender documents before relying on a probable match, bidder name, or warranty statement.
  4. Inspect the open-source build scripts and detailed provenance note for filtering and indexing logic.

Found stale or incorrect source data? Open a GitHub issue with a public source link. Do not include an API key, private personal data, or an unredacted road photo.
