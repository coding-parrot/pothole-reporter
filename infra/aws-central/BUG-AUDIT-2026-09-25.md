## Fixes

1. Receipt PutCommand spread receipt.id over the intended RECEIPT# key. GetCommand
   and observation consumption use the prefixed key, so legitimate submissions failed.
   Corrected write order; added bounded, conditional recovery of unexpired legacy rows.
   Original rows remain for rollback and normal TTL expiry. Core still verifies
   installation, observation, image hash, location, verdict and expiry.
2. KGIS JSON objects without a valid features array were considered successful empty
   responses, potentially asserting outside_state. Invalid payloads now yield unknown
   ownership and remain retryable, never a false jurisdiction claim.

Receipt regression failed before the fix. Expanded server suite: 72/72 passing.
Production package was downloaded and compared: the hotfix changes only the two
service modules. No infrastructure, quota, secret or IAM setting was changed.

## Remaining

- Karnataka-only authoritative routing does not establish nationwide road ownership.
- KGIS availability remains an external dependency; unknown ownership must not be
  converted to a guessed commissioner/contractor.
- No verified YOLO fallback is configured.
- Old clients still contain capture/UI bugs until a signed Play update rolls out.
- Successful live report retries after deployment need subsequent production evidence;
  unit tests and health checks alone do not establish that all tester failures ceased.
